# 完整定编流程

## 命令约定

在 `E:\AI\dingbian` 中运行：

```powershell
python run_classifier.py --input "<当前文件>" --output-dir "outputs" --stage <阶段>
```

每次从命令输出读取新的绝对文件路径，将它作为下一阶段的 `<当前文件>`。不要继续使用原始文件。

每个阶段结束后运行：

```powershell
python "E:\AI\dingbian\skills\dingbian\scripts\inspect_workbook.py" "<当前文件>"
```

根据 `next_action` 继续：`fix_workbook_selection` 表示主表无法唯一识别；`resolve_foundation_data` 表示先补基础数据；`prepare_standard_units` 表示新增或刷新标台数；`run_standard_format_and_decomposition` 表示进入主表格式和完整分解；`run_decompose_extra_summary` 表示额外订单信息汇总缺少最新产能规划指标；`run_classify` 表示分解结果已具备但缺少最终分类；`review_unclassified_data` 表示分类已执行但仍有未分类行，需要向用户说明并询问是否继续补规则。

注意：不要凭文件名判断阶段完成。最新项目结果中可能出现文件名包含“分类结果”，但工作簿仍缺少“分类结果汇总表/未分类数据”的情况；必须以检查器输出为准。

## 1. 自动识别主表

1. 只接受非 `~$` 开头的 `.xlsx` 或 `.xlsm` 主工作簿。
2. 用 `inspect_workbook.py` 自动识别名称符合 `W数字-W数字...周排产明细` 的工作表。
3. 若 `target_sheets` 为空，报告实际工作表名称并暂停；若存在多个候选，列出候选并让用户指定。不要自行猜测主表。
4. 后续所有阶段均以检查器返回的 `target_sheet` 为准，不要凭文件名或工作表顺序判断。

## 2. 基础清理与基础数据异常并行准备

1. 优先运行 `prepare-foundation-data`，一次性完成：
   - 删除 `订单数` 为空的行；
   - 删除 `线体` 为空的行；
   - 删除 `物料编码` 为 `Z4U6010100` 的订单行；
   - 删除行后刷新 `系数` 和 `钣金型号` 的 VLOOKUP 当前行引用，避免公式仍查旧行号；
   - 摘取 `系数` 异常到 `系数补充`；
   - 摘取 `钣金型号` 异常到 `钣金型号补充`，异常包含 `#N/A`、`N/A`、空白和 `0`；
   - 摘取 `物料描述` 异常到 `物料描述补充`。

```powershell
python run_classifier.py --input "<当前文件>" --output-dir "outputs" --stage prepare-foundation-data
```

2. 若需要分阶段重试，也可以先运行 `cleanup-order-rows`，再按 `prepare-coefficients`、`prepare-sheet-metal`、`prepare-material-description` 连续执行。不要因为前一项仍有待补就停止后两项的摘取。
3. 运行 `inspect_workbook.py` 检查三项待补数量。
4. 若 `coefficient_pending`、`sheet_metal_pending`、`material_description_pending` 任一大于 0，暂停进入主表格式、标准台数和分解阶段，先按下面方式回填。

防错原则：所有基础数据补充都优先采用“补充表确认机制”。也就是外部查询表或 BOM 能匹配出的候选值，先写入对应的 `系数补充`、`钣金型号补充` 或 `物料描述补充`，并在关键字段前增加匹配说明/来源列供人工确认；确认后再通过对应 `apply-manual-*` 阶段写回主表。只有用户明确要求“直接回填主表”时，才使用直接 `fill-*` 阶段。若已经生成分解结果后又发现基础数据仍有待补，不要把该文件视为完成；补齐后从受影响的下游阶段继续重跑到 `classify`。

删除同步原则：用户在 `系数补充`、`系数仍缺失`、`钣金型号补充`、`物料描述补充` 或 `物料描述仍缺失` 任一补充环节中说明某些订单“未上单”“删除”或“可删除”时，该删除决定适用于整张排产主表和全部基础补充信息。执行删除/清理后，必须刷新主表，并重新刷新三类补充表，确保这些订单不再出现在任何补充表中。不要只刷新触发删除的那一张补充表，也不要让已删除订单继续停留在其他补充表里。

删除后的固定续跑方式：

1. 先记录用户确认删除的订单唯一识别信息，优先记录 `订单号`、`物料编码`、`线体`、`订单数` 和所在补充表。
2. 使用项目已有的单阶段清理命令处理主表；不要手工批量删除文件或目录。
3. 清理命令输出新文件后，立即重新运行 `prepare-foundation-data`；如果需要分阶段重试，则运行 `prepare-coefficients`、`prepare-sheet-metal`、`prepare-material-description` 连续刷新三类补充表。
4. 再运行 `inspect_workbook.py`，并人工核对刚才删除的订单是否仍出现在 `系数补充`、`系数仍缺失`、`钣金型号补充`、`物料描述补充` 或 `物料描述仍缺失` 中。
5. 只要已删除订单仍存在于任一补充表，就不得进入 `prepare-standard-units`、格式整理、分解、额外汇总或 `classify`；需要继续刷新或暂停说明当前业务阶段没有完成同步删除。

## 3. 已处理结果中临时删除特定订单

适用场景：用户已经拿到处理好的定编结果，但本月临时要求删除某些品牌、客户、机型或订单，例如“这个月删除追觅订单”，需要在已有结果基础上单独删除这些订单后重新跑定编。

必须按以下安全流程处理：

1. 可以复用该特定机型、品牌或客户在分类/分解规则中的识别条件来查找候选订单行，例如按物料描述、物料编码段、备注、客户/品牌、项目、线体等规则筛出候选。
2. 不要直接按 `类型`、分解表分类名称、汇总表项目或颜色整批删除。`类型` 是分解后的归类结果，只能作为辅助线索，不能单独作为删除依据。
3. 候选必须回落到主表具体订单行清单，优先展示 `订单号`、`物料编码`、`物料描述`、`客户/品牌`、`项目`、`备注`、`线体`、`订单数` 等字段。
4. 向用户反馈候选行数、订单数合计、涉及线体、代表性物料编码/物料描述，并等待确认。若候选条件不唯一或可能误伤，必须暂停让用户确认。
5. 用户确认后，只删除候选清单中确认的订单行；删除后刷新主表、标台数和所有受影响的结果表。
6. 删除发生在已分解或已分类结果文件中时，不要只改汇总表；必须从受影响的下游阶段重新执行：基础数据检查 → `prepare-standard-units` → `format-main-sheet` → 完整分解 → `decompose-extra-summary` → `classify`。若基础数据待补仍为 0，可以从 `prepare-standard-units` 继续；若待补大于 0，先回到基础补齐。

追觅专项规则：

- `T7/P7/T5/P5/追觅单洗` 和 `T7/P7/T5/P5/追觅烘干` 是分解大类；如果对话中用户按习惯说成 `T7P7/T3/P5/追觅烘干`、`T7P7/T3/P5/追觅单洗` 等相近叫法，也按同一风险处理。该类中可能同时包含 T7/P7/T5/P5 非追觅订单和追觅订单。
- 用户说“删除追觅订单”时，可以使用 `decompose-t7p7t5p5-dreame` 中对追觅的识别逻辑查找候选；但最终只能删除主表中原始字段明确命中 `追觅`、`DREAME`、`DREMA` 或用户确认属于追觅的订单行。
- 不得把整个 `T7/P7/T5/P5/追觅单洗` 或 `T7/P7/T5/P5/追觅烘干` 大类全部删除；这种做法会误删 T7/P7/T5/P5 中非追觅机型。
- 如果只能通过分解后的 `类型` 看到 `T7/P7/T5/P5/追觅...`，但原始 `物料描述`、`客户/品牌`、`项目` 或 `备注` 不能区分追觅，必须暂停并向用户索取明确订单号、物料编码或外部清单。

## 4. 系数回填

若缺失且用户提供了唯一系数查询表，运行：

```powershell
python run_classifier.py --input "<当前文件>" --output-dir "outputs" --stage fill-coefficients --coefficient-lookup "<系数查询表>"
```

若没有查询表，暂停并索取。查询后仍缺失，要求用户填写当前结果中的“系数补充”或“系数仍缺失”，保存并关闭 Excel。用户返回后运行 `apply-manual-coefficients`。

若用户确认“系数补充”或“系数仍缺失”中的剩余订单是未上单、无需处理或可删除的订单，运行：

```powershell
python run_classifier.py --input "<当前文件>" --output-dir "outputs" --stage cleanup-coefficient-supplement-rows
```

清理后必须按“删除同步原则”刷新三类补充表；不能只让主表或系数补充表变干净，而让相同订单继续留在钣金型号或物料描述补充表中。

## 5. 钣金型号回填

若缺失且用户提供了唯一钣金型号查询表，运行：

```powershell
python run_classifier.py --input "<当前文件>" --output-dir "outputs" --stage fill-sheet-metal --sheet-metal-lookup "<钣金型号查询表>"
```

没有查询表时暂停索取。查询后仍缺失，要求用户填写“钣金型号补充”。用户返回后运行 `apply-manual-sheet-metal`。

若用户提供的是 BOM 表，且表内包含 `BOM号`、`物料描述`，需要按主表当前“钣金型号缺失/异常”的 `物料编码` 匹配 `BOM号`，再取同一 BOM 下 `物料描述` 含 `箱体组件` 的行回填钣金型号，运行：

```powershell
python run_classifier.py --input "<当前文件>" --output-dir "outputs" --stage suggest-sheet-metal-bom --sheet-metal-bom-lookup "<钣金型号BOM表>"
```

该阶段只把 BOM 匹配到的箱体组件候选写入“钣金型号补充”，不直接写主表。用户确认候选值正确、必要时手工修改“钣金型号补充”后，再运行 `apply-manual-sheet-metal` 写回主表。若用户明确要求跳过确认，也可以运行 `fill-sheet-metal-bom` 直接写回主表。

BOM 候选后仍缺失，再刷新“钣金型号补充”供用户人工补充。若用户在钣金型号补充环节确认某些订单未上单或要求删除，同样按“删除同步原则”处理：删除后刷新主表，并重新刷新系数、钣金型号、物料描述三类补充表，确认被删除订单不再出现。

注意：`箱体组件` BOM 表通常是同事按“钣金型号补充”里的缺失物料编码从系统导出的整机 BOM，里面可能同时包含滚筒和波轮。BOM 回填不能按线体一刀切，也不能覆盖主表已有正常钣金型号；只能回填当前仍为 `#N/A`、`N/A`、空白或 `0` 的行，并要防止明显滚筒/波轮组件错配。

钣金型号为 `0` 的原因和处理：

- `0`、`0.0`、`0.00` 在本流程中不是有效钣金型号，而是处理异常值，必须和 `#N/A`、`N/A`、空白一样纳入 `钣金型号补充`。
- 默认不要先怀疑用户提供的原始排产表或查询表本身含有 0。结合 7 月处理经验，`钣金型号=0` 更常见于删除特定型号订单、回退到“剔除追觅版本”、或基于已处理结果续跑后，主表行号发生变化，但 `钣金型号` 的 VLOOKUP 仍引用旧行号，导致部分行显示为 0；`系数` 列也可能同时存在类似旧行号问题。
- 另一个常见诱因是删除订单后继续沿用旧的 `钣金型号补充`、旧 BOM 候选或旧结果表，没有重新生成补充表，导致旧原始行号、旧公式结果或旧候选残留。
- 诊断时先查看出现 0 的行：核对该行 `物料编码` 与 `钣金型号`/`系数` 公式引用的编码单元格是否是同一当前行；若公式仍指向旧行号，先按公式刷新处理，不要把 0 当作真实缺失来源。
- 处理顺序：先从最后一个可信版本或当前结果执行删除/清理；随后立即重新运行 `prepare-foundation-data` 或至少连续运行 `prepare-coefficients`、`prepare-sheet-metal`、`prepare-material-description`，刷新 `系数` 和 `钣金型号` 的 VLOOKUP 当前行引用，并重新生成三类补充表。
- 刷新后再检查 `钣金型号=0` 行数；如果 0 已清零，继续后续流程。如果仍有 0，再按正常缺失处理：先用 `fill-sheet-metal` 查询表回填；仍缺时用 `suggest-sheet-metal-bom` 生成 BOM 候选；用户确认候选后运行 `apply-manual-sheet-metal`。
- 不要把 `0` 当作人工已确认值，也不要因为单元格不是空白就跳过；只要主表或补充表中的钣金型号仍为 `0`、`0.0` 或 `0.00`，就表示 `sheet_metal_pending` 仍未解决，不能进入标台数、分解或 `classify`。
- 若刷新和查询/BOM 后仍出现 0，需要向用户说明对应物料编码、线体、物料描述、公式引用情况和匹配来源，让用户确认正确钣金型号或确认订单未上单/可删除；若确认删除，则按“删除同步原则”刷新所有补充表。

`钣金型号补充` 表列顺序：

- 该表需要把 BOM 匹配来源和候选值放在前面，便于人工确认；推荐列顺序为：`原始行号`、`周次`、`BOM匹配说明`、`BOM箱体组件原文`、`钣金型号`、后续原字段。
- `BOM匹配说明` 用于显示 `BOM候选，待确认`、`BOM未匹配`、`疑似线体类型不匹配，未自动写入` 等状态。
- `BOM箱体组件原文` 用于显示 BOM 中匹配到的箱体组件文本或候选来源。
- `钣金型号` 列放在这些说明列之后，用户不用横向拉到最后就能同时看到 BOM 来源、候选值和需要确认/填写的钣金型号。

若用户确认“物料描述补充”或“物料描述仍缺失”中的剩余订单都是未上单订单，运行：

```powershell
python run_classifier.py --input "<当前文件>" --output-dir "outputs" --stage cleanup-missing-material-description-rows
```

该阶段会删除主表中当前物料描述为空白或 `#N/A/N/A` 的订单行，并刷新系数和钣金型号公式行引用。清理后必须按“删除同步原则”重新刷新三类补充表，确认被删除订单不再出现在系数、钣金型号或物料描述任何补充表中。

## 6. 物料描述回填

若缺失且用户提供了唯一物料描述查询表，运行：

```powershell
python run_classifier.py --input "<当前文件>" --output-dir "outputs" --stage fill-material-description --material-description-lookup "<物料描述查询表>"
```

没有查询表时暂停索取。查询后仍缺失，要求用户填写“物料描述补充”或“物料描述仍缺失”。用户返回后运行 `apply-manual-material-description`。

## 7. 标台数、主表格式、完整排单分解与最终分类

基础数据三项全部补齐后，按以下固定顺序逐个运行；每个阶段必须使用上一阶段的新输出：

1. `prepare-standard-units`：在 `订单数` 前新增或刷新 `标台数`，公式为 `系数 * 订单数`。
2. `format-main-sheet`：刷新标台数格式，设置表头、边框、隐藏列、增加 `类型` 列，并清除已应用的筛选条件但保留筛选按钮。
3. `decompose-skd`：处理滚筒线 SKD。
4. `decompose-rolling-remarks`：处理滚筒线 CKD、三星、双滚筒和备注类规则。
5. `decompose-t7p7t5p5-dreame`：处理滚筒线 T7/P7/T5/P5/追觅。
6. `decompose-t9p9`：处理滚筒线 T9/P9。
7. `decompose-t9p9-dryer`：处理滚筒线 T9/P9 干衣机。
8. `decompose-t10p10`：处理滚筒线 T10/P10。
9. `decompose-c6-heat-pump-dryer`：处理滚筒线 C6 热泵干衣机。
10. `decompose-composite-penguin-c6`：处理滚筒线复式、企鹅、C6 等分类。
11. `decompose-rolling-final`：完成滚筒线普通烘干、内销、外销等收尾分类。
12. `decompose-wave-basic`：处理波轮线 CKD、LG、塑料机、P7/P9、SKD 等基础分类。
13. `decompose-wave-final`：完成波轮线内销/外销铁皮、变频等收尾分类。
14. `decompose-extra-summary`：生成或刷新 `排单分解表明细`、额外订单信息汇总和 `线体分类明细表`。
15. A 线/D 线公斤段主表回写与着色校验：确认 A 线内销、D 线外销公斤段细分不仅已汇总到 `线体分类明细表`，也已同步回写主表 `类型` 列，并给主表 `钣金型号`、`渠道` 两列按公斤段填充区分颜色。
16. `classify`：生成最终 `分类结果汇总表` 和 `未分类数据`。

不要把 `decompose-extra-summary` 提前到完整分解之前。
`classify` 是当前定编默认必跑的最终阶段。没有生成“分类结果汇总表”和“未分类数据”时，不要称为定编完成。若用户要求中途暂停确认，暂停后记录当前文件、已完成阶段和下一阶段，确认后从当前阶段继续，不要回到原始排产文件重跑。

补充约定：

- `format-main-sheet` 会在整理主表格式前再次刷新 `标台数` 公式和格式，避免新增计算列后表头、边框、数字格式不一致。
- `decompose-extra-summary` 生成的 `排单分解表明细` 需要汇总滚筒、波轮各分类订单数，并校验分类合计与主表合计。
- `decompose-extra-summary` 生成或刷新当前版本的 `线体分类明细表`，填充 `月度排单数`、`线体排单数`、`线体标台数`、`订单数`、`转产时间`、`返修损失/影响工时` 和右侧 `订单不良宽放工时预算表`；`线体标台数`、`转产时间` 和 `影响人工时` 显示保留 1 位小数。
- `线体分类明细表` 中某个线体班组模板缺少本次实际出现的分类机型时，允许在该线体班组内自行增加一行，填好分类名称和数量；最终回复必须单独说明新增了哪些线体班组和分类。

## 8. 异常处理

- 文件不存在：报告绝对路径并暂停。
- 文件名以 `~$` 开头：要求关闭 Excel 并提供原文件。
- `outputs` 中存在对应的 `~$` 临时锁文件或打开工作簿失败：要求保存并关闭 Excel，再重试当前阶段；不要处理临时锁文件。
- 扩展名不支持：要求 `.xlsx` 或 `.xlsm` 主工作簿。
- 找不到主工作表：报告实际工作表名称并暂停。
- 找到多个主工作表：请用户选择。
- 查询表字段不符合要求：原样报告缺少字段，不尝试模糊映射。
- Excel 文件被占用：要求保存并关闭后重试当前阶段。
- 任一阶段失败：不要跳过，也不要从头重跑；保留最后成功输出并从失败阶段重试。
