# Dingbian

## 核心原则

- 固定使用项目 `E:\AI\dingbian` 中的现有程序和业务规则；不要在技能中重写分类逻辑。
- 使用 `run_classifier.py` 的命令行阶段，不要启动需要桌面弹窗的月度向导。
- 不修改原始工作簿。始终把阶段输出写入 `E:\AI\dingbian\outputs`，并把上一步输出作为下一步输入。
- 逐阶段执行和检查。缺少查询表、人工数据或存在多个候选文件时，暂停并向用户明确索取所需内容。
- 不要猜测查询表。只有一个明确候选时才自动使用。
- `classify` 是定编默认必跑的最终阶段；除非用户明确要求只做前置处理，否则最终结果必须包含“分类结果汇总表”和“未分类数据”。
- 最新流程必须覆盖：自动识别主表、基础清理、三类基础异常并行准备、系数/钣金型号/物料描述回填、标台数新增或刷新、主表格式整理、滚筒线分解、波轮线分解、排单分解表明细、额外订单信息汇总、线体分类明细表、A 线/D 线公斤段主表回写与着色校验、全线体物料编码分类复核、最终 `classify` 和最终 Excel 视图校验。
- 当前线体分类输出以“线体分类明细表”为准；旧“各线体分类明细表”只作为历史数据来源，使用后可从结果工作簿删除。
- “线体分类明细表”必须使用 2026-07-09 确认的新版本式：左侧按线体班组分块，列为 `类别`、`产品类型`、`月度排单数`、`线体排单数`、`线体标台数`、`订单数`、`转产时间`、`返修损失`；右侧必须包含“订单不良宽放工时预算表”。旧的“滚筒线体分类明细-订单数/标台数、波轮线体分类明细-订单数/标台数”四块汇总版不再视为合格交付。
- 处理“线体分类明细表”时，如果某个线体班组模板里缺少本次实际出现的分类机型，允许在该线体班组内自行增加一行，但最终回复必须单独告知用户新增了哪些线体班组和分类。
- 结果工作簿涉及 Excel 兼容性修复或二次写入时，优先用 Excel 自身打开原可信底稿并另存，避免程序保存后的工作簿触发 Excel “发现内容有问题”的修复弹窗。
- 默认保留主表和结果表中的公式，不要为了消除 Excel 修复弹窗而批量把公式冻结成固定值。若用户打开时出现“发现内容有问题”弹窗，先说明选择“是/修复”通常不影响定编结果，并核对关键表是否完整；只有用户明确要求“无弹窗优先且接受公式不再联动”时，才另存固定值兼容版，并在文件名和回复中明确标注。
- 对 A 线内销、D 线外销公斤段细分，最终结果必须同时满足两个落点：`线体分类明细表` 的月度排单数正确；主表 `类型` 列已回写细分名称，且主表 `钣金型号`、`渠道` 两列按公斤段填充区分颜色。只汇总到线体明细但未回写主表时，不得视为最终交付完成。
- 在 `decompose-extra-summary` 的分类回写中，先识别“热泵洗烘一体机”，再执行 A/D 线公斤段细分；公斤段仍以钣金型号优先，仅当钣金型号没有命中时才能使用 `物料描述` 的已确认型号前缀兜底。具体前缀、优先级与颜色规则必须读取 `references/workflow.md`，不得根据相近型号自行扩展。
- 物料描述回填并完成重新分解后，必须执行全线体物料编码分类复核，不只复核 A 线和 D 线：所有线体订单都按物料编码前缀检查分类大方向，`U605...` 为干衣机、`U60101...` 为单洗、`U60102...` 为烘干。只自动更正规则可唯一确定的错分；其余冲突写入“物料编码分类复核”供人工确认，不能因类别名称相近而混分。
- 最终结果工作簿必须检查 Excel 视图状态：滚动条可见，活动工作表和活动单元格正常，`线体分类明细表` 等结果表不得保留深行冻结窗格（例如 `B89`）。冻结窗格应位于表头附近（推荐 `B4`）或取消冻结，避免用户无法上下滑动。
- 用户在系数、钣金型号或物料描述任一补充环节确认某些订单“未上单”“删除”或“可删除”时，删除后必须同步刷新主表和所有补充表；不能让已删除订单继续留在 `系数补充`、`系数仍缺失`、`钣金型号补充`、`物料描述补充` 或 `物料描述仍缺失` 中。
- 用户要求在已处理好的定编结果中单独删除某类订单时，可以复用该机型/品牌在分类规则中的识别条件去查找候选，但最终必须落到主表具体订单行清单并让用户确认；不能按已分解后的大类整批删除。特别是“删除追觅订单”只删除按追觅识别条件明确命中或用户确认属于追觅的订单，不得删除整个 `T7/P7/T5/P5/追觅单洗` 或 `T7/P7/T5/P5/追觅烘干` 大类。
- `钣金型号` 为 `0`、`0.0` 或 `0.00` 要视为处理异常值，而不是有效型号；优先怀疑删除订单、回退版本或续跑后 `系数`/`钣金型号` VLOOKUP 仍引用旧行号，必须先刷新公式和补充表，再用查询表或 BOM 候选补齐。
- 不要仅凭文件名包含“分类结果”判断完成；必须以 `inspect_workbook.py` 返回的工作表、待补数量和 `next_action` 为准。
- 禁止递归或批量删除文件和目录。不要使用 `del /s`、`rd /s`、`rmdir /s`、`Remove-Item -Recurse` 或 `rm -rf`。

## 开始处理

1. 确认用户提供了一个非 `~$` 开头的 `.xlsx` 或 `.xlsm` 排产工作簿。
2. 若有多个可能的排产工作簿，列出文件名并请用户指定；不要自行选择。
3. 确认工作簿没有被 Excel 独占打开。
4. 运行只读检查：

```powershell
python "E:\AI\dingbian\skills\dingbian\scripts\inspect_workbook.py" "<工作簿路径>"
```

5. 自动识别并使用唯一的 `W数字-W数字...周排产明细` 主工作表；若找不到或找到多个，报告检查结果并暂停，等待用户指定。
6. 阅读 [references/workflow.md](references/workflow.md)，严格按其中的顺序执行完整流程。

## 沟通与续跑

- 需要系数查询表时，请用户提供包含物料编码及“系数”或“等级D”的查询文件。
- 需要钣金型号查询表时，请用户提供包含“物料编码”和“钣金型号”的 Excel。
- 需要通过 BOM 补钣金型号时，默认先运行 `suggest-sheet-metal-bom` 写候选到“钣金型号补充”，等待用户确认后再运行 `apply-manual-sheet-metal`；只有用户明确要求跳过确认时才运行 `fill-sheet-metal-bom`。
- “钣金型号补充”表应把 `BOM匹配说明`、`BOM箱体组件原文` 放在 `钣金型号` 前，推荐列顺序为：`原始行号`、`周次`、`BOM匹配说明`、`BOM箱体组件原文`、`钣金型号`、后续原字段，方便不用拉到最后就能看到 BOM 来源和候选值。
- 需要物料描述查询表时，请用户提供包含“物料编码”和“物料描述”的 Excel 或文本导出。
- 自动查询后仍有缺失时，告诉用户当前结果文件路径和要填写的工作表；等待用户保存并关闭后，从对应 `apply-manual-*` 阶段继续。
- 用户在任一补充表中指定订单未上单或要求删除时，先记录这些订单的唯一识别信息，再执行项目现有单阶段删除/清理命令；删除后必须重新运行基础异常准备或对应刷新步骤，让三类补充表同时反映删除后的主表状态。
- 每次暂停都明确记录：当前结果文件、已完成阶段、下一阶段、缺少的文件或信息。
- 用户要求继续时，优先使用对话中最后一次明确返回的当前结果文件；若文件不存在，再检查 `outputs`，有多个候选则询问。
- 若发现 `~$` 临时锁文件或工作簿无法打开，要求用户保存并关闭 Excel 后再从当前阶段继续。

## 提效原则

- 每次重跑先以 `inspect_workbook.py` 的 `next_action` 为准；如果基础数据三项待补已经为 0，不要无意义地回到基础清理或补充表阶段，从 `prepare-standard-units` 或检查器指示的下一个阶段继续。
- 质量日报 `.xls` 或已知会触发 Excel 安全拦截的日报，默认用非交互解析方式读取，不先尝试 Excel COM 打开，避免“先拦截再换方案”的重复耗时。
- 结果后处理尽量合并执行：质量日报不良率、线体分类明细模板、A/D 公斤段主表回写与着色、冻结窗格修正完成后，再做一次 Excel COM 重算/另存和只读验证；不要在每个小修补后都单独重算另存。
- 对比历史结果时优先比较关键业务表和值缓存：主表、排单分解表明细、线体分类明细表、分类结果汇总表、未分类数据；只有发现业务差异或用户要求时，才做全工作簿逐格/样式对比。

## 阶段检查

基础数据异常先并行准备：系数、钣金型号、物料描述可以连续摘取并生成补充表，不因前一项缺失而阻止后一项检查。

每个补齐阶段结束后运行 `inspect_workbook.py`：

- `coefficient_pending > 0`、`sheet_metal_pending > 0`、`material_description_pending > 0` 任一存在时，不得进入标准台数和分解阶段。
- 若某一项缺失，继续完成另外两项的补充表准备后，再统一向用户索取查询表或人工补充。
- 阶段命令失败时，保留当前文件，报告错误和失败阶段；不要跳过。
- 如果检查到分解结果表已存在但基础数据仍有待补，不要宣称完成；先补齐基础数据，再从会受影响的下游阶段继续重跑到 `classify`。
- 删除未上单订单后必须检查所有补充表；若已删除订单仍出现在任一补充表中，不得继续进入标台数、格式、分解或 `classify`，必须先刷新补充表或暂停说明当前业务阶段未完成同步刷新。
- 临时删除已分解结果中的品牌、客户、机型或订单时，可以先按相应分类规则筛出候选，再输出候选行数、订单数合计和关键字段让用户确认；未确认前不执行删除，且删除后必须从会受影响的下游阶段重新跑到 `classify`。
- 基础数据无待补后，必须先新增或刷新 `标台数`（位于 `订单数` 前，公式为 `系数 * 订单数`），再整理主表格式；整理格式时清除已应用的筛选条件但保留筛选按钮。
- 如果额外订单信息汇总缺少 `外协烘道数量`、`滚筒喷粉数量`、`波轮喷粉数量`、`PCM板中需喷涂前门板的箱体数量` 任一指标，先运行 `decompose-extra-summary`。
- 如果“排单分解表明细”和“线体分类明细表”已存在但“分类结果汇总表”不存在，下一步是运行 `classify`。

## 最终交付

完成所有阶段后再次运行只读检查，并向用户返回：

- 最终结果文件的绝对路径。
- 主工作表名称和数据行数。
- 系数、钣金型号、物料描述各自剩余待补数量。
- “未分类数据”行数。
- 是否生成“排单分解表明细”“线体分类明细表”“分类结果汇总表”和“未分类数据”。
- “线体分类明细表”是否为新版式：左侧线体班组分块加右侧“订单不良宽放工时预算表”；若仍是四块汇总旧版式，必须重跑 `decompose-extra-summary` 或修正程序后再交付。
- 额外订单信息汇总是否包含外协烘道、滚筒喷粉、波轮喷粉、PCM 箱体 4 个产能规划指标。
- A 线内销、D 线外销公斤段是否已同步回写主表 `类型` 列，并给主表 `钣金型号`、`渠道` 两列按公斤段着色；如有缺失，必须说明并修正后再交付。
- 是否已完成全线体物料编码分类复核；如生成“物料编码分类复核”表，必须说明待人工确认的冲突数量和主要冲突类型。
- 最终工作簿是否仍保留公式、是否仅做 Excel 重算/另存而未批量冻结固定值；若提供固定值兼容版，必须单独说明。
- 最终工作簿是否可以正常滚动，特别是 `线体分类明细表` 的冻结窗格不得停在 `B89` 等深行位置。
- 运行中出现的警告或仍需人工处理的异常。

只有基础数据无待补、完整排单分解成功、额外订单汇总成功且 `classify` 成功生成分类结果后，才称为“定编完成”。若“未分类数据”行数大于 0，仍返回结果文件，但必须把未分类数量作为异常说明并询问是否需要继续补分类规则。

## 质量日报默认处理

- 当用户提供质量日报用于填写“订单不良宽放工时预算表”时，若文件是 `.xls`，或近期同类日报已触发 Excel “受保护视图/检测到文件存在问题/不能打开此文件”等安全拦截，默认不要先用 Excel COM 尝试打开原文件。
- 默认处理方式：先用只读二进制解析或项目内可用的非交互解析方式读取质量日报中的 `过程合格率&top问题` 工作表，提取各线体班组的 7 月累计合格率，并按 `100% - 合格率` 写入“线体分类明细表”右侧不良率。
- 只有在非交互解析失败、工作表结构变化、或无法唯一定位线体班组合格率时，才向用户说明并请求确认；不要因为 Excel 安全拦截而反复尝试打开同一个日报。
- Excel COM 仍可用于最终结果工作簿的重算和另存，以降低用户打开结果文件时出现“发现内容有问题”修复弹窗的概率；该步骤不要用于优先读取质量日报 `.xls`。
